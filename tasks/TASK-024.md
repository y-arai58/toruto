# TASK-024: 前面カメラの向き補正をやり直す

- status: done
- priority: critical
- started_at: 2026-07-30
- completed_at: 2026-07-31

## 症状

前面カメラに切り替えると、縦持ちでプレビューが横向き（頭の頂点が左）になる。
保存した写真も横向きで、さらに左右反転している。背面は正常。

TASK-019（設定タイミングの修正）でも直らなかった。

## 調査の経緯（実機 4 回）

`AVCaptureConnection` の `videoRotationAngle` / `isVideoMirrored` は、
**設定しても実態と一致せず、読み戻した値も実態と一致しない**ことが実機検証で分かった。
経路（プレビュー用 `videoOutput` / 撮影用 `photoOutput`）ごとにズレ方も違い、
共通の計算式にまとめようとした試みは 3 回とも実機で失敗した。

| ラウンド | やったこと | 結果 |
|---|---|---|
| 1（TASK-019） | 設定を `commitConfiguration` の後に移す | 変化なし。原因はタイミングではなかった |
| 2 | 接続を無効に固定し、コード側で回転を適用 | 前面が二重回転。接続に前段の 90 度が残ったまま届いていた |
| 3 | 接続から読み戻した実測値を基準に計算 | 写真だけ直り、プレビューは直らず。経路ごとに実態が違うと判明 |
| 4 | プレビューはバッファの形（横長/縦長）で判定、写真は EXIF に一任 | 両方直ったが、写真がさらに横向き＋左右反転 |

ラウンド 4 で写真が壊れたのは、こちらが接続へ書き込んでいた回転・ミラー設定が原因だった。
その書き込みを全廃し、**写真は元の実装（AVFoundation が書いた EXIF をそのまま使う）に戻した**。

## 最終的な実装

| 経路 | 向きの決め方 |
|---|---|
| プレビュー | 届いたバッファが横長か縦長かを見て回転を決める（`CameraOrientation.forPreview`） |
| 写真 | 向きは触らず EXIF に一任（`CIImage(data:options:[.applyOrientationProperty: true])`） |

鏡像はプレビュー・保存写真とも前面のときだけ適用する（ユーザー要望で見え方を揃えた）。
保存側の反転は Crop・フィルター・日付スタンプより**前**に行うので、スタンプの文字は反転しない。

接続のプロパティ（`videoRotationAngle` / `isVideoMirrored`）への依存は、
読み取り・書き込みとも完全に無くなっている。
