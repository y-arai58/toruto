# UI Guideline

## 原則

- **すぐ撮れる**: 起動から撮影まで最短。設定画面より撮影画面を優先する
- **Simple / Stylish / Fun**: 装飾は最小限、質感で魅せる
- 「カメラアプリ」としての UI。加工アプリの UI（スライダー羅列等）にしない

## 画面構成（MVP）

```text
┌─────────────────────┐
│  プリセット名 / 切替       │ ← 上部: 現在のカメラ表示
│ ┌─────────────────┐ │
│ │                 │ │
│ │  中央フレーム       │ │ ← 保存される領域を明示
│ │  (プレビュー)       │ │
│ │                 │ │
│ └─────────────────┘ │
│                     │
│  [切替]  ◉  [プリセット]  │ ← 下部: シャッター中心
└─────────────────────┘
```

## ルール

- 中央フレームは **3:4 固定**（プリセットによらず共通）。サイズはピンチで変更（換算 13〜260mm・中央固定）
- 中央フレームの外側は暗くして「保存されない領域」を直感的に伝える
- シャッターボタンは画面下部中央、片手で届く位置に固定
- プリセット切り替えは横スワイプ or 横スクロールで 1 アクション
- 文字は最小限。アイコンと視覚表現で伝える
- ダークベースの配色（カメラアプリとして没入感を優先）

## フィードバック

- シャッター時: 視覚（フラッシュ/フレーム点滅）+ 触覚（Haptics）
- 保存完了: 控えめなサムネイル表示。モーダルやアラートは出さない
- 権限拒否時のみ、設定アプリへの導線を明示する

## 起動体験

カメラの起動（`AVCaptureSession.startRunning()`）は実機で 1 秒前後かかり、
これはハードウェア側の待ち時間なのでアプリからは縮められない。
そのため「待ち時間を隠す」方向で設計する。

- `LaunchScreen.storyboard`（背景 `LaunchBackground` + `LaunchLogo` 100x128pt 中央）
  → 起動直後の空白と、ライトモード端末での白フラッシュを消す
- `LaunchOverlay` が storyboard と同じ背景色・ロゴ・サイズ・位置で引き継ぐ
  → 起動画面からアプリ本体への切り替わりが見えない
- オーバーレイの退場条件は **プレビューの最初のフレームが届いたとき**（`hasPreviewFrame`）
  → 「オーバーレイは消えたのに映像はまだ真っ黒」という間を作らない
- 待機中はロゴが呼吸（scale 1.0 ⇄ 1.04）、退場は 0.32 秒でスケールアップ + フェード
  → スピナーは出さない（待たされている感を強調しないため）
- カメラが応答しない場合も 4 秒でオーバーレイは必ず外す

ロゴは `Design/generate_launch_logo.py` で AppIcon と同じモチーフから生成する。

## アクセシビリティ

- タップ領域は 44pt 以上
- Dynamic Type はプリセット名など文字要素で対応
